# 工作流程（全栈补充）

本文是 [任务优先工作流](task-first-workflow.md) 的补充，不是独立流程。原文档的工作流、状态机、回写规则、文档结构全部照常执行，下面每一节都标明了追加到原文档的哪个位置，只写全栈新增的判断。

## 补充「风险评估」

在原有条目之外，额外关注：

- **接口契约变更**（请求/响应结构、鉴权方式）→ 高风险，前后端需同步，确认兼容策略；破坏性变更优先加版本号或并行新旧接口。
- **全局生效的改动**（总览中 `route: "*"` 类）→ 高风险，说清影响面和回归范围。
- **数据库 schema 变更**（加字段、改类型、迁移）→ 高风险，影响存量数据，确认回滚方案。
- **跨仓库依赖**（前端等接口、后端等 UI 对接）→ 中风险，确认先行模拟还是等待。
- **环境配置变更**（端口、环境变量、依赖版本）→ 中风险，确认影响范围。

## 补充「附录1：任务状态机」

- 「本方」可以是前端、后端或全栈。判断「能否闭环」时要考虑前后端联动：后端接口已落地但前端未对接、或前端已完成但依赖的接口尚未实现，都属于依赖他方（2.2 / 3.3）。
- 其余状态流转、终态路径与例外不变。

## 补充「附录2：任务标题与粒度」

后端任务优先以**接口**为边界，比按文件或目录更容易对上需求，也更容易写验证条件：

| 场景 | 任务拆法 |
| --- | --- |
| 改一条接口的入参、返回值、处理逻辑 | 一条任务 |
| 一次需求动同一模块的多条接口 | 按接口拆成多条任务 |
| 全局能力（请求体解析、鉴权、限流、超时、错误格式） | 一条任务，总览用 `route: "*"` |
| 内部重构、工具函数、schema 迁移 | 一条任务，没有对应接口，任务里写清代码位置 |

判断口径：外部能观测到的行为变化用接口作边界，内部实现调整用模块作边界。标题带上归属，如 `用户服务-实现登录接口`、`登录页-对接登录接口`、`全站-请求体解析上限调整为 20MB`。

## 补充「附录3：文档结构」中的验证条件

验证条件不限于 UI，按实际交付层选择，接口类任务至少写一条可直接执行的调用：

- 接口：调用接口确认返回结构和状态码。
- 数据：查询数据库确认数据已写入或更新。
- 日志：检查服务日志确认无异常。
- 端到端：从前端操作触发，确认后端响应正确。
- 全局改动：至少覆盖一条正常接口和一条异常接口，确认对所有接口生效。
