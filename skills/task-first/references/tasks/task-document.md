# 任务文档（TASKS.md）

本文规定 `TASKS.md` 的状态机、任务粒度与文档写法，与具体开发流程无关：`task-first` 用它维护开发中的任务，`code-review` 用它回写审查结论。与 `overview.yaml` 放在同一目录。

## 任务状态机

### 状态与流转

按「本方还有代码要写吗 → 能否闭环交付 → 是否验证」三步分支：

```
                 ┌─ 本方写完、能闭环 ──► 2.1 待验证 ──用户/自行验证──► 3.1 已完成
                 │
1 处理中 ────────┼─ 本方写完、依赖他方 ► 2.2 待验证 ──用户/自行验证──► 3.2 待交接
                 │
                 └─ 本方零改动、问题属他方 ─────────────────────► 3.3 待交接
```

| 步骤 | 状态 | 进入条件 | 必填元信息 |
| --- | --- | --- | --- |
| 1 | 处理中 | 还在开发，**本方仍有待写的代码**；仅用于大任务中间态或被打断的情况。注意：等待他方（接口、权限、资源）不属于处理中，应按 2.2 / 3.3 走 | 无 |
| 2.1 | 待验证 | 本方代码已落地，且可以直接闭环交付 | 验证条件 |
| 2.2 | 待验证 | 本方代码已落地，但依赖其他方确认或补齐能力（如依赖接口修改，接口实现尚未确定） | 验证条件、交接给、交接原因 |
| 3.1 | 已完成 | 2.1 经用户确认通过，整件事闭环 | 验证条件（沿用待验证时写入，不再改写） |
| 3.2 | 待交接 | 2.2 经用户确认通过，余下工作需服务端等其他角色进行 | 验证条件、交接给、交接原因 |
| 3.3 | 待交接 | **本方零代码改动**，排查后确认任务完全属于他方，无本方内容可验，直接交接 | 交接给、交接原因 |

其中能否闭环交付是关键，比如你无法确定接口是否支持参数，请如实告知，比如新增 UI，但不确定接口是否支持，不属于闭环，建议交接到服务端。

「本方」可以是前端、后端或全栈。判断能否闭环时考虑前后端联动：后端接口已落地但前端未对接，或前端已完成但依赖的接口尚未实现，都属于依赖他方（2.2 / 3.3）。

如何处理用户反馈：
- 用户反馈有问题：停留或调整回 *待验证*，重新修复后继续等待确认。
- 用户表达肯定但有多条 *待验证* 无法确定指向：主动询问是哪一条，不要擅自全部标记完成。

### 进入终态的唯一路径

*待验证* 是进入任一终态的必经环节，*处理中* 不得直跳 *已完成* 或 *待交接*。两个例外：

1. 改动对用户不可见（纯重构、类型修复、依赖升级、注释调整等）且构建或测试已通过，可直接写 *已完成*；
2. 本方零代码改动、问题完全属于他方（3.3），可直接写 *待交接*——此时没有本方内容可供验证，不需要用户确认。

严禁以「改动很简单、逻辑很直接、应该没问题、只改了两行代码、我已检查过没报错」为由直接写 *已完成*——编译通过只说明代码能跑起来，不说明效果符合用户预期。

### 判断示例

场景一：用户说「登录按钮改成蓝色」，你改了一行 CSS。
- 正确：任务状态写 *待验证*，补充验证条件「聚焦到登录页，确认按钮已变为蓝色」。
- 错误：状态直接写 *已完成*，理由是改动很简单。

场景二：紧接上一轮，用户回复「可以了」。
- 正确：系统自动将该任务流转至 *已完成*，你无需再次回写 TASKS.md。
- 错误：新增一条「登录按钮颜色调整」并标记 *已完成*，原来那条待验证任务留在文档里不动。

场景三：用户说「加个导出 Excel 的按钮」，导出需要服务端提供接口。
- 正确：引导前向用户确认是否需要模拟实现还是仅交接，如果前端先实现，完成按钮与交互后写 *待验证*，补充验证条件以及交接相关信息。
- 错误：自行假定接口地址与参数，或跳过用户确认直接写 *待交接*。

场景四：你把组件里的重复逻辑抽成公共函数，页面表现无变化，构建通过。
- 正确：状态写 *已完成*，符合准入条件第 1 条。
- 错误：状态写 *待验证*，让用户去验证一个看不见的改动。

场景五：本轮只回答了用户「这个页面的数据从哪来」的提问，没改任何源码。
- 正确：不改动 TASKS.md。
- 错误：新增一条任务来记录这次问答。

## 任务标题与粒度

标题是跨轮匹配任务的依据，必须稳定、具体、可复用：

- 写「在哪个页面或模块做什么」，如 `登录页调整按钮样式`，而不是 `修改样式`；
- 一条任务对应用户视角的一件事，不要按文件来拆分。
- 外部可观测的行为变化用接口作边界，内部实现调整用模块作边界：改一条接口的入参、返回值或处理逻辑为一条任务；一次需求动同一模块的多条接口按接口拆多条；请求体解析、鉴权、限流、超时、错误格式等全局能力为一条任务；内部重构、工具函数、schema 迁移为一条任务并写清代码位置。
- 标题带上归属，如 `用户服务-实现登录接口`、`登录页-对接登录接口`、`全站-请求体解析上限调整为 20MB`。

**粒度适中**：既不事无巨细，也不遗漏关键任务，核心是保障准确性和可维护性。

## 文档结构

每个任务由「二级标题 + 加粗列表元数据 + 一句话摘要」组成。

- **标题**：格式为 `## T-001 任务名称`，ID 单调递增，新增任务时取文档中最大 ID + 1，位数不足三位时补零（超过 999 继续往上，不截断）。
- **元数据**：用 `- **字段名**：值` 的形式列出，既能加粗展示，也能被程序按 `**字段**：内容` 稳定解析。
- **一句话摘要**：紧跟元数据的引用块（`>` 开头），一句话讲清这个任务是做什么的，让用户扫一眼就懂。摘要要有落点，说清「给谁/在哪个功能上做什么」，避免「优化了逻辑」这类空话；具体到页面、模块或文件，写清做了什么、还差什么。

### 元数据字段说明

字段取值使用固定枚举，便于解析。何时必填见状态机表，此处只规定写法：

| 字段 | 用途 | 取值 |
| --- | --- | --- |
| 更新时间 | 该任务最近一次被改写的时间 | `YYYY-MM-dd hh:mm` |
| 状态 | 任务状态 | 处理中 / 待验证 / 待交接 / 已完成 |
| 交接给 | 交接接手方 | 角色 |
| 交接原因 | 为什么要交接出去 | 一句话说明，如缺少的接口/权限/信息 |
| 风险与决策 | 记录本次改动的决策风险、已知妥协或不合理之处 | 一句话说明，无则不写 |

字段名和取值严格按上表使用，不要自造，保证可被程序稳定解析。

**风险与决策** 为可选字段，仅在存在明确的代价、妥协或不合理之处时填写。没有实际风险不要编造，宁缺勿滥。

**验证条件** 独立写在元数据列表之外，紧跟一句话摘要之后，用编号列表按步骤言简意赅地列出用户该如何操作及预期观察结果。状态流转至终态后不再改写，原样保留作为验收记录。

验证条件按实际交付层选择，接口类任务至少写一条可直接执行的调用：接口调用确认返回结构与状态码，数据查询确认已写入或更新，日志检查确认无异常，端到端从前端操作触发确认后端响应；全局改动至少覆盖一条正常接口和一条异常接口。

### 完整示例

```TASKS.md
# 任务列表

## T-001 报表页增加导出 Excel 功能

- **更新时间**：2026-09-28 15:30
- **状态**：处理中

> 在报表页新增「导出」按钮，把当前表格数据下载为 Excel。

## T-002 编辑页新增上传头像能力

- **更新时间**：2026-09-27 11:05
- **状态**：待交接
- **交接给**：服务端
- **交接原因**：缺少上传与保存头像的接口能力，需要服务端提供具体接口

> 编辑页已完成头像上传的前端 UI 展示，具体上传与保存逻辑待接口设计实现后敲定。

**验证条件**：
1. 定位到编辑页，点击头像区域，确认可以选择本地图片并正常预览

## T-003 登录页调整按钮样式

- **更新时间**：2026-09-28 14:12
- **状态**：待验证

> 在登录页把登录按钮改为品牌蓝，增大了按钮与输入框的间距，并添加了登录按钮的背景渐变动画，提升登录按钮的视觉效果。

**验证条件**：
1. 定位到登录页，确认登录按钮已变为品牌蓝，并且登录按钮和输入框间距变大
2. 鼠标悬停登录按钮，确认出现背景渐变动画

## T-004 列表页新增数据导出能力

- **更新时间**：2026-09-26 17:40
- **状态**：待验证
- **交接给**：服务端
- **交接原因**：真实导出下载依赖服务端提供导出接口，前端无法独立完成
- **风险与决策**：
已确认前端先进行模拟接口实现，模拟代码请在最后上线前与服务端联调完毕并去除。

> 列表页已完成导出按钮与弹窗交互，等待用户确认前端交互后，交接给服务端补齐导出接口。

**验证条件**：
1. 聚焦列表页，点击「导出」按钮，确认弹出导出弹窗，点击后提示导出失败

## T-005 列表页上传解析支持 csv 格式文件

- **更新时间**：2026-09-25 09:18
- **状态**：已完成

> 列表页新增上传 csv 文件解析功能，上传后自动解析并刷新表格展示。

**验证条件**：
1. 定位到列表页，点击上传csv文件，提示成功并自动刷新表格内容
```
